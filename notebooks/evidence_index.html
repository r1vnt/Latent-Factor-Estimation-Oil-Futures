Evidence Index -- WTI Term-Structure Latent-Factor Study¶

This notebook is an evidence index, not a re-derivation. It maps claim -> number -> the script that produced the number -> the JSON artefact holding it. A 26-perturbation battery over an 18-contract three-factor panel is not a cell, it is an afternoon; re-fitting it here would (a) make this notebook the slow thing everyone avoids running and (b) risk printing a number that differs from the paper in the last digit, which is worse than not printing it at all.

One source of truth: every number below is read from results/*.json via the same loader the paper's own numbers.tex is generated from (scripts/emit_numbers_tex.py). Paper and notebook read the same files; if a fit is re-run and a number moves, it moves in both places, or this notebook's own panel-hash check below catches the mismatch.

Three compute tiers, by runtime:

  • Tier A (live): <5s -- EIA settlement check, power calculations, block bootstraps over stored difference series, every plot, the order-reversal demonstration. Runs every time.
  • Tier B (flagged): single fits. Gated by RECOMPUTE below, default False. The point isn't that anyone runs it -- it's that the ten lines producing the headline are visible, with no sleight of hand.
  • Tier C (never here): the 26-perturbation battery, 50+ fits, multi-start diagnostics. Live in explore/, emit JSON, cited by path.

def load_result(name):
    """The one loader every Tier A/loaded cell uses. Asserts the
    artefact's panel_hash matches this session's canonical panel --
    a result from a different panel is not silently trusted."""
    d = json.loads((ROOT / "results" / name).read_text())
    prov = d.get("_provenance", {})
    h = prov.get("panel_hash")
    assert h == CANONICAL_HASH, f"{name}: panel_hash {h} != canonical {CANONICAL_HASH}"
    _inventory["loaded"] += 1
    return d

9. Results that did not survive¶

A section most portfolio notebooks omit. The original claim, the diagnostic that killed it, the corrected number -- and the order-reversal check recomputed live, in about a second, because it's the cheapest demonstration in the whole document and the one a skeptical reader will ask for first.

Claim as first computed: the filter beats a random walk one-step- ahead on 17/18 contracts, by 300-800x (explore/53). What killed it: filter_uv's sequential univariate updating means contract i>0's residual is conditioned on contracts 0..i-1's same-day updates -- not a genuine forecast for anything but the first contract processed. Order-reversal check below: the likelihood must be exactly order-invariant (it is); the per-contract error pattern must flip with the order (it does).

def _filter(log_f, tau):
    sys3 = _raw_system3(p, smooth, tau, 1 / 252)
    x0, P0 = initial_state3(log_f, tau, p)
    return filter_uv_contributions(np.ascontiguousarray(log_f), np.ascontiguousarray(sys3["Z"]),
        np.ascontiguousarray(sys3["d"]), np.ascontiguousarray(sys3["T"]), np.ascontiguousarray(sys3["c"]),
        np.ascontiguousarray(sys3["Q"]), np.ascontiguousarray(sys3["Hdiag"]), np.zeros((sys3["n"], 3)),
        np.ascontiguousarray(x0), np.ascontiguousarray(P0))
